01｜啟動、登入與資料確認

  1. 執行 02_Start.cmd 後，保持黑色視窗開啟，使用畫面顯示的網址。
  2. 登入 uat-admin，密碼是初始化時你設定的密碼。
  3. V4模式應看到36筆PO、20筆應付；原始快照與工作台分開。合成模式只有基本測試資料，完整BI案例請用V4模式。
  4. 重新整理一次，仍應能登入及讀取相同資料。

預期：可登入；日期及資料母體與來源一致。尚未登錄任何本次驗收假交易。

02｜五種角色與PO範圍

測試帳號操作應有結果
uat-admin開帳號與稽核頁看得到五個帳號與角色
uat-finance維護PO與收付款可送出；不可銀行覆核
uat-reviewer銀行覆核、財務議題可覆核他人交易；不可改交易金額
uat-sales開PO與交付頁只看得到PO A；不能看PO B、公司備份或完整快照
uat-viewer開戰情室可閱覽，不能送出變更或匯出公司備份

多帳號請用 Edge一般視窗、Edge InPrivate、Chrome一般視窗或不同瀏覽器設定檔。相同瀏覽器的一般分頁會共用登入；不要把它們當成不同使用者。

03｜PO草稿、送出與重新載入

  1. 用uat-finance登入，進入「金像收款管理」→「PO與交付」，選PO A。
  2. 負責人改成 UAT-FIN-A；驗收改「驗收中」；依據填「UAT交付測試，非實際驗收」。金額與已收基準保持來源值。
  3. 按表單的「保存工作台更正」。此時仍是記憶體草稿。
  4. 按頂部「送出至伺服器」，成功後會重新載入。
  5. 用另一個已登入的唯讀視窗按「載入最新資料」，確認負責人已更新。

預期：只有送出成功才成為共用資料；重新整理後仍保留。原始快照數字不改寫。

04｜多PO收款核銷

用uat-finance進入「金像收款管理」→「銀行核銷」→「登錄收款」。日期採下方測試工作截止日，不用今天日期替代。

銀行交易編號UAT-REC-001銀行實入TWD1,040
本筆稅額TWD50匯費TWD10
PO A分配未稅600PO B分配未稅400
銀行核對待核對證據／備註UAT假交易，非實際收款

未稅分配 600＋400＋稅50＝銀行1,040＋匯費10。期款先選「未指定」，避免核銷到原始來源的既有計畫。

按表單保存，再按頂部送出。若測試庫已有相同UAT編號，請改用全新編號，不重複登錄。

預期：新增1筆交易、2筆PO分配；PO A未收減600、PO B減400。銀行1,040不重複當成未稅回款。

05｜錯誤資料必須擋下

  1. 新增UAT-REC-BAD：未稅600、稅30、匯費0，銀行實入刻意填600。差額30，應擋下。關閉表單，不送出錯誤資料。
  2. 再試一次使用既有UAT-REC-001憑證，應拒絕重複入帳。
  3. 對PO A填超過目前未收的核銷額，應拒絕超額。
  4. 若計畫顯示「未知基準PO」，對該PO試填核銷，應要求先補基準，不能視為0。不要為了測試任意改原基準。

預期：錯誤交易沒有存入資料庫；原本正確的交易仍在。

06｜銀行覆核與登錄分工

  1. 財務登錄後，不要在同一交易選「已核銀行」重新登錄。
  2. 換另一個瀏覽器的uat-reviewer，開「帳號／覆核／稽核」頁。
  3. 找到UAT-REC-001，按「銀行覆核」，輸入「UAT獨立覆核測試」。
  4. 回uat-finance戰情室載入最新資料，確認交易顯示已覆核。

預期：保留原登錄人，覆核人為不同帳號；覆核不能改金額、日期或核銷分配。

07｜供應商付款與分幣

  1. 用uat-finance進入鷹眼應付模組，切換「工作台」，按「登錄付款」。
  2. 選本頁列出的應付項目，金額填100（該設備原幣），憑證UAT-PAY-001，日期用測試截止日，銀行狀態待核，備註UAT假交易。
  3. 表單保存後，按頂部送出，重新載入工作台。
  4. uat-reviewer可在覆核頁對該筆付款執行銀行覆核。

預期：該設備原幣未付減100；CNY與USD仍分開，沒有直接加總。原表快照不變。

08｜13週資金情境

  1. 用uat-finance在PO A新增分期：日期用測試截止日、未稅1,000、預計銀行淨流入1,050、狀態「已確認」，填「UAT合約情境」作為依據與證據。
  2. 按頂部送出。在資金情境輸入：模型起日＝測試截止日、期初資金100,000、安全水位20,000、每週其他淨支出1,000。這些全是測試假設。
  3. 若有已確認外幣付款計畫，再填測試匯率；尚未確認的原排程不會自動算入。
  4. 按頂部送出，核對完整、保守與重度壓力三種情境。只保留這筆新確認回款且沒有確認付款時，完整排程第1週應為100,050，第13週88,050。
  5. 把期初資金清空測試，應顯示缺資料；確認後可回填100,000並送出。

預期：資金情境只取已確認排程；缺參數不給假缺口結論。70%延4週、50%延8週是壓力假設，不是違約機率。

09｜兩個使用者編輯衝突

  1. Edge用uat-finance，Chrome用uat-admin。兩邊先載入同一版本的PO A。
  2. 兩邊各開PO A表單，分別把負責人改UAT-A與UAT-B，填修改依據，先各自保存成草稿。
  3. Edge按頂部送出成功；Chrome先不要重新載入，直接送出舊版本。
  4. Chrome應顯示版本衝突，UAT-B草稿仍留在畫面；按「下載未送出草稿」，再載入最新資料比較。

預期：先送者成功；後送者不會覆蓋。按載入最新資料後看到UAT-A。

10｜作廢與稽核

  1. 用uat-finance在覆核管理頁將UAT-REC-001作廢，理由「UAT測試結束」。
  2. 回戰情室重載，PO A、PO B應回復核銷前餘額；交易仍列出已作廢。
  3. UAT-PAY-001亦可依相同方式作廢，原幣未付回復。
  4. uat-admin或uat-reviewer開稽核頁，載入最近200筆，檢查原登錄、覆核及作廢操作者與前後值，完整鏈驗證應通過。

預期：不用刪除交易也能回復餘額；歷史與理由保留。新增的測試分期若不再需要，可取消並送出。

11｜備份、重啟與隔離還原

  1. uat-admin按「匯出公司備份」，或雙擊03_Backup.cmd。確認檔案非空，保存於自己授權的位置。
  2. 在啟動視窗按Ctrl+C停機，再執行02_Start.cmd；重新登入，確認資料仍在。
  3. 雙擊04_Check.cmd，應看到integrity、auditChain、foreignKeys都為true。
  4. 依下載包docs/LOCAL_WINDOWS.md的「隔離還原」步驟，還原到全新restore資料庫。不要把原UAT資料庫改成還原目標。

預期：重啟資料不遺失；還原外鍵與稽核完整。還原的歷史帳號全部停用，需要新還原管理者。
